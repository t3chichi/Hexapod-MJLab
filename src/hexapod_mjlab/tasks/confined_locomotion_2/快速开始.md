## 3. Play：浏览器可视化与无界面推理

Play只加载新任务网络权重，不更新参数；每次从新episode和零时间状态开始。hit10模式只能加载 `hit_only_10m` checkpoint，旧的 `all_endpoints` checkpoint会被拒绝。使用已通过当前源码10迭代短训的hit10 checkpoint；这是有限工程模型，不代表行走质量：

```bash
HIT10_CKPT="logs/verification/confined_locomotion_2/20261023_far_hit10_shorttrain_final_hit10/training/final_checkpoint_full_000010.pt"
CKPT="$HIT10_CKPT"
HIT10_SELECTION="src/hexapod_mjlab/tasks/confined_locomotion_2/assets/fixed_channels/v1_hit10/near_x6_far_x10.npz"

python -B scripts/experiments/confined_locomotion_2/play.py \
  --checkpoint "$CKPT" \
  --seed 20261023 \
  --gpu 0 \
  --output "logs/confined_locomotion_2/play_$(date +%Y%m%d_%H%M%S)" \
  --port 8094 \
  --far-sampling hit_only_10m \
  --raycast-mode sparse --sparse-selection-path "$HIT10_SELECTION"
```

当前近端256点与远端128点均使用XYZ FPS；选点后仍按现有角度键排序。hit10下每帧far实际valid数可能小于128。sparse选择的近端/远端候选倍率为6/10；全量raycast可以使用相同sampling，但改变full/sparse模式需要显式Play scan override。有限工程模型不代表已学会行走。

Play默认发现并校验 `assets/fixed_channels/v1/`、`v1_independent/` 与 `v1_hit10/`；也可用重复的 `--sparse-selection-dir NEWDIR` 添加自定义离线目录。显式 `--sparse-selection FILE` 仍可直接启动，并优先覆盖该文件metadata对应的倍率组合。保持原sampling规则之外，跨 `all_endpoints` 和 `hit_only_10m` 一律拒绝。

```bash
SPARSE_SELECTION="$HIT10_SELECTION"
SPARSE_CKPT="$CKPT"
```

然后运行：

```bash
python -B scripts/experiments/confined_locomotion_2/play.py \
  --checkpoint "$SPARSE_CKPT" \
  --seed 20261023 \
  --gpu 0 \
  --output "logs/confined_locomotion_2/play_sparse_$(date +%Y%m%d_%H%M%S)" \
  --far-sampling hit_only_10m \
  --raycast-mode sparse --sparse-selection-path "$SPARSE_SELECTION"
```

该checkpoint仅代表有限工程链路。完整续训严格校验sampling、grouping、full/sparse mode及selection身份，不允许跨配置恢复。同sampling权重评估同一catalog的另一个mode或selection时，可显式使用 `--allow-scan-override`；跨sampling始终拒绝。旧dynamic grouping或legacy sampling权重不能作为hit10示例。GUI中的 `Fixed near-channel boundary rays` 显示固定T1分组的角域边界射线。

例如，启动时同时发现一个自定义离线目录并显式使用该目录中的选集：

```bash
python -B scripts/experiments/confined_locomotion_2/play.py \
  --checkpoint "$SPARSE_CKPT" \
  --seed 20261023 --gpu 0 \
  --output "logs/confined_locomotion_2/play_custom_$(date +%Y%m%d_%H%M%S)" \
  --far-sampling hit_only_10m \
  --raycast-mode sparse \
  --sparse-selection NEWDIR/near_x2_far_x3.npz \
  --sparse-selection-dir NEWDIR \

```

Play验证metadata与catalog后，将该组合加入GUI倍率选项。缺少的组合会提示不可用并禁用Apply；不生成选集文件，也不改用其他倍率。倍率不改变网络实际接收的256+128点数。

例如，要用同sampling的sparse checkpoint评估full raycast，可启动时显式放开Play扫描配置检查：

```bash

  --allow-scan-override
```

该开关只影响Play权重评估，不放宽训练checkpoint的完整恢复身份校验。snapshot、segment summary和根summary记录训练扫描身份、实际扫描身份及 `cross_configuration` 标志。

启动后在浏览器打开 **http://127.0.0.1:8094**。默认暂停，未设置步数预算；点击 `Single step` 推进一个20 ms控制步，或 `Pause / continue` 连续运行。`Exit`或终端`Ctrl+C`关闭服务器。关闭浏览器标签不会停止程序。

- `vx m/s`、`vy m/s`、`wz rad/s`滑块修改后，点击 `Apply command` 生效；`Zero command`将指令归零。合法范围依次为 `[-1.5,1.5]`、`[-1,1]`、`[-1,1]`。CLI初始指令使用 `--command 0.10 0 0`。
- `Reset episode`重置全部环境、清零时间状态和指令、重新扫描，并保持暂停；正式跌倒后只能通过该按钮开始新episode。故障冻结后应退出并检查日志。
- `Raycast mode`可切换 `full`/`sparse`；`Near candidate multiplier` 和 `Far candidate multiplier` 是两组独立下拉，随附默认选集含4/5/6/8组合及near×6/far×10。自定义倍率来自经校验的离线目录。Play只显示已发现且通过身份校验的组合。组合文件缺失时明确提示并禁用Apply。控件只修改待应用配置；只有点击 `Apply acquisition + reset` 才切换raycast模式或selection，不切换far sampling规则。状态栏显示当前far sampling和valid点数；跨 `all_endpoints` 与 `hit_only_10m` 需以匹配checkpoint重新启动Play。Apply后网络权重SHA保持一致，新episode、命令和GRU状态清零并保持暂停。不同catalog/grouping不允许跨配置评估。
- `Near 256`、`Far 128 (current scan)`显示实际输入点；远端只有当前扫描，没有10帧窗口。颜色区分命中与no-hit点。可切换候选点、`Fixed near-channel boundary rays`固定角域边界射线、六边形包络和根部目标高度。边界显示不是动态锥体加BASE-x平面的裁切。没有地面预测头或地面监督图层；平面网格仅为物理场景参照。
- `View`切换BASE/WORLD。所有扫描点保留采集时BASE坐标，WORLD仅用当前姿态投影显示，**不做历史点运动补偿或建图**。状态区分别标明输入与动作后姿态的控制步。
- 在 `Pick cloud`选择near/far，填写相应 `input index`，点击 `Query raw source`查看原始射线编号、扫描身份和no-hit状态。索引对应各分支排序后的输入槽，填充槽会标为invalid；更换扫描自动清除旧选择。
- 暂停期间切图层、切坐标和查点只使用缓存，不推进物理、扫描、噪声随机流或GRU状态。初始化、改变指令和重置会计算显式preview，但不提交时间状态。
- 新任务默认8094，旧任务默认8093，可以分别启动；端口被占用时改用 `--port 8095` 等空闲端口。`--num-envs`默认1，界面可选择显示行。

有限步数自动运行的浏览器模式：

```bash

```

默认 `--save-interval 50`：每累计完成50轮保存 `checkpoint_full_000050.pt`、`checkpoint_full_000100.pt` 等，正常结束另有 `final_checkpoint_full_XXXXXX.pt`。中断时从最近成功写入的完整文件恢复，不保存半轮状态；所有周期文件保留、不自动删除。续训需保持原保存间隔。指标定义与验证见[监控与保存](../../../../docs/tasks/confined_locomotion_2/training/监控与保存.md)。

查看训练曲线（将路径换成实际run目录）：

```bash
read -r -p "训练run目录: " TRAIN_RUN
tensorboard --logdir "$TRAIN_RUN/tensorboard" --host 127.0.0.1 --port 6006
```

## 5. 从完整checkpoint继续训练

支持新任务的 `checkpoint_full_*.pt` 和 `final_checkpoint_full_*.pt`。新增监控/保存逻辑改变源码身份，此前far-hit配对短训的legacy/hit10模型仍可用于匹配sampling的Play，但不能在当前源码严格续训。当前源码恢复回归见[GPU检查](../../../../logs/verification/confined_locomotion_2/20261023_training_observability_gpu/checks.json)，其中checkpoint来自刻意设为1的保存间隔，用于有限工程检查；正常训练默认50。

完整恢复要求原种子、环境数、源码、配方（含保存间隔）、模型、设备、sampling和扫描身份匹配。full与sparse、不同selection或far sampling之间不能完整恢复。续训sparse hit10时重新传入相同的sampling及selection；默认50的模型可直接使用下列命令，其他间隔需补充原 `--save-interval`。

```bash
read -r -p "新任务完整checkpoint文件路径: " RESUME_CKPT
read -r -p "原训练种子: " TRAIN_SEED
read -r -p "原训练环境数: " TRAIN_ENVS
read -r -p "本次新增迭代数: " EXTRA_ITERS
HIT10_SELECTION="src/hexapod_mjlab/tasks/confined_locomotion_2/assets/fixed_channels/v1_hit10/near_x6_far_x10.npz"

python -B scripts/experiments/confined_locomotion_2/train.py \
  --seed "$TRAIN_SEED" \
  --num-envs "$TRAIN_ENVS" \
  --iterations "$EXTRA_ITERS" \
  --resume-checkpoint "$RESUME_CKPT" \
  --far-sampling hit_only_10m \
  --raycast-mode sparse \
  --sparse-selection-path "$HIT10_SELECTION" \
  --gpu 0
```

`--iterations`表示**本次新增迭代数**，不是累计目标。续训会恢复环境、扫描时钟、原轨迹和镜像轨迹的时间状态、Adam及随机流，并创建新的run目录；不需要另传 `--log-root`。Play只读权重并清零时间状态，与完整续训的行为不同。

## 6. GPU专项集成检查

下列通用 `check_gpu.py`、viewer、fixed-sparse及benchmark命令使用legacy `all_endpoints`默认身份；它们保留为相应历史检查配方，不是hit10 GPU验收。hit10真实姿态Warp/parity专项已通过，报告见第2节；此前 `20261023_far_hit10_gpu/` 是失败尝试，不作为验收证据。需要核对legacy采集、镜像、保存恢复、同一rollout优化重放和超时重置时使用 `check_gpu.py`。它会执行有限采集和参数更新，包含恢复诊断及额外优化重放，不是只读检查，也不是正式长训练。

## 8. 参数区别与常见错误

| 情况 | 处理方式 |
|---|---|
| 提示不认识 `--max-iterations` 或 `--gpu-id` | 新任务分别使用 `--iterations`、`--gpu` |
| 想打开浏览器Play | 使用第3节命令，打开127.0.0.1:8094；默认暂停，点击Single step或Pause / continue |
| 提示工程验证预算超限 | `--engineering-validation`只能配 `--iterations 1`、`--num-envs 1`或`2` |
| 提示目录已存在 | 为GPU专项检查和Play换一个新的输出目录 |
| checkpoint任务或身份不匹配 | 确认是当前XYZ FPS采样版本的 `_2` 完整模型；旧角采样版本不兼容；续训另核对seed、环境数、源码和设备 |
| CUDA不可用 | 激活 `hp_mjlab`，检查 `nvidia-smi` 与 `python -c 'import torch; print(torch.cuda.is_available())'` |
| CUDA显存不足 | 从1或2个环境的工程验证开始；更换环境数后的新训练不能冒充原环境数的完整续训 |
| 想调整点数、GRU维度或辅助监督 | 当前CLI没有这些开关；实现位置和约定见[新任务说明](../../../../docs/tasks/confined_locomotion_2/README.md)，变更会影响checkpoint兼容性 |

终端停止程序使用 `Ctrl+C`；保存边界见第4节。当前注册默认不授权训练，应使用本页显式训练入口。

当前GPU切换和真实CUA浏览器验收链接记录的是legacy `all_endpoints` sampling身份。当前已通过的hit10真实pose parity、Warp点云stage2、当时源码的配对短训和严格恢复见本页第2节；Play浏览器验收已通过，详见第2节；长训规模尚未确定，工程基线不代表学习效果通过。
