# 2026-10-26：Terrain Memory 与训练性能记录

本文整理三阶段 Terrain Memory 工程闭环及独立性能工作树 stage 1–8 的结论。正式配置/接口见[任务入口](../../../../docs/tasks/confined_locomotion_2/README.md)，日常命令见[快速开始](../../../../src/hexapod_mjlab/tasks/confined_locomotion_2/快速开始.md)。本页是阶段记录，不是新的任务指令。

## Terrain Memory 工程闭环

**几何。** 第一阶段建立实际编译 Heightfield 的查询闭环：Heightfield 采样为 `[Y,X]` 米制高度，监督网格在当前动作前 Root XY/Yaw 下映射，按 `iy*17+ix` 排列 11×17 标签；目标值为世界地表高度减 Root Z。查询来自编译模型中的地形，不另造标签地图。首轮几何范围 X±1.2 m、Y±0.9 m 是验证候选，后来训练选择了 X±0.75 m、Y±0.65 m。曾遇到启动姿态穿透、直接射线路径误差及用软接触 witness 反推表面的错误假设；这些不是验收结果。支持范围仍限静态单值 Heightfield，不能外推到任意斜坡出生、动态/倾斜地形或复杂地形行走。

**采集与重放。** 第二阶段把地形射线接入已有扫描管线，并让 Runtime 负责 50 Hz 控制、10 Hz 扫描、reset 和 episode 身份。Height 标签与对应控制步严格配对，保存在 rollout 独立监督字段；标签不进入在线 observation 或 Actor。当前地形 MDP 适配只改变必要的地面查询来源，原奖励公式、权重和六维形态监督语义不变。普通与镜像重放按同一个 Root XY/Yaw 网格翻转 Y 行，保持高度符号。早期 fixture 曾在同一观测身份下改写状态，被缓存契约拒绝；最终验证通过真实 reset 构造 fixture，没有放宽检查。

**高度辅助训练。** 第三阶段为时间特征增加 `Linear(187,187)` 高度头，输出 11×17 米制高度图。监督损失对每个有有效点的样本先算有效点 MSE，再对有效样本等权平均；镜像与原样本各占一半。高度图和预测不进入 Actor 或 Critic，梯度只经辅助损失到高度头及两个 GRU。λ_height=1.0 是工程起步候选，不是经学习效果选择的最终权重。当前训练网格 X±0.75 m、Y±0.65 m；地形策略学习、记忆消融、泛化及动态地形尚未验证。

上述三阶段在 RTX 4050 完成有限几何、标签/重放、一次 PPO 更新、严格恢复和只读 Play 检查。它们证明工程链路能运行，不证明高度预测泛化或机器人能稳定行走。早期详细 CPU/GPU 检查、界面操作、冻结源码和模型日志曾存于本地 `logs/verification/confined_locomotion_2/`；克隆仓库不依赖这些 ignored 文件。原始阶段记录和源码快照应按当时身份解释，不回写旧结果。

## 性能优化 stage 1–8

实验限定于固定 near×6/far×10、`hit_only_10m`、真实 sparse rollout、FP32、原 24 步 BPTT、原镜像与 20 次 Adam 更新。优化过程中保留网络层、参数形状、损失、PPO样本/顺序、reset 和 learning-rate 语义；每个 checkpoint 仍绑定严格源码身份。阶段记录如下：

1. **基线与首轮原型。** 识别出 PPO 重放按环境逐行调用点 GRU是主要速度瓶颈，点 GRU 的反向激活是显存峰值来源。批量编码减少 Python/GPU 调用；激活重计算用额外计算换显存，保留每轮对真实点云重新编码和编码器梯度。
2. **时序、输出头与采集批处理。** 在保持完整时序语义下批量处理时序状态/共享输出头及 collector 的缓存缺失行。128 环境 Flat 有限正式入口完成；Terrain 128 完成两轮与严格续训。结果只用于确认工程吞吐和保存恢复链路。
3. **重放准备和分块扩展。** 将PPO旧动作/分布/包络标签、点序验证与打包复用放到每轮重放计划；collector 采用有界批次，点编码分块从 64 扩到 128。512 环境真实 GPU 有限更新完成。收集、仿真和奖励语义保持不变。
4. **执行模式选择。** 将低显存 activation recomputation 设为默认，保留显式速度模式作对照。RTX 4050 上 512 环境未能完成的速度模式出现 OOM；未据此推定其他 GPU 的容量。
5. **传感与观测批处理。** 仅对到期 world 批量调用地形 raycast，批量搬运 observation/identity，同时保留逐行随机数和缓存语义。使用实际扫描/噪声对照验证几何、观测和随机流；早期验证脚本对 NaN 时间戳比较不当，修正的是验证脚本，不改变任务实现。
6. **点 GRU 分块 256。** 将重放块从 128 提到 256；packed grouping 的更密集候选未采用，因为512环境使用256行dense分组出现OOM，128行dense分组较慢且峰值更高。性能值是有限同步测量，不是统计基准。
7. **候选块上限 1024。** 在配置中提高点编码分块上限。RTX 4050 实际批次 1024/1280 在 256 环境 OOM；768 是本机完成的最大实际批次。128 环境首轮真实 rollout 只有 640 个唯一扫描行，因此该验证没有实际测到 1024 行一次处理。不能将候选上限理解为成功验证的硬件容量。
8. **重放准备和主机同步收束。** 每轮重放计划预备并堆叠原始/镜像 observation、标签和 mask，有限值标志分阶段在设备侧归约，更新后批量读取 loss 指标；未跨 Adam 更新复用权重相关结果。CPU 检查 148 项通过。保持 low-memory、FP32、两个隐藏状态独立、24 步梯度、mask 和 20 次更新。

### Stage 8 测量

同一份真实 128 环境 rollout、相同模型/Adam 初态、low-memory、FP32、配置分块上限 1024；每个候选完成两次 20-step Adam 更新。基线 PPO update 中位数 5.5440 s、Torch 峰值 2045.7 MiB；接受的重放准备优化为 4.9127 s、2053.1 MiB，更新时间降低 11.387%，峰值增加约 7.4 MiB。参数、Adam state、指标差值均为 0，RNG 与 20 项 learning-rate 序列相同。实验性 fused Adam 中位数 4.9372 s，没有超过接受方案的收益，故未采用。

随后 Terrain Memory 128 环境正式入口完成两轮，共 6,144 env transitions 和 40 次 Adam 更新；PPO update 分别约 4.9176 s 与 5.7205 s，严格续训通过。同机 Flat 128 环境单轮有限工程更新约 4.8725 s。性能数字来自有限 RTX 4050 Laptop 测量，显存为 PyTorch allocator 统计，不含所有 Warp/driver 分配。实际 128 环境首轮只处理了 640 个唯一扫描行；它不是大批次容量证明。5090 未测，长训稳定性和学习效果未验收。
