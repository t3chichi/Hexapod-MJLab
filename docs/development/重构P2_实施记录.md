## P2.1 配置基线

使用现有注册表与工厂生成一次只读语义快照；快照按字段值、类名、callable 身份、数组/张量内容比较，故意忽略类所在模块路径，以便区分“实现移动”和“语义变化”。快照包含：

- 四个注册任务的 `env_cfg`、`play_env_cfg`、`rl_cfg` 与 runner；
- v1/v2 Flat、Terrain、Tripod 的显式训练/Play 工厂；
- v1/v2/Terrain/Tripod 的工程或正式 RL 配方。

修改前后快照逐字节相同（SHA-256 对比，diff 为空）。注册任务与关键默认值：

| 任务 | Runner | 默认 env | reward / termination | Play 默认 |
|---|---|---:|---:|---|
| `El-4090-Confined-Locomotion-Flat` | `ConfinedLocomotionRunner` | 64 | 17 / 4 | 通用 Flat，无 reward/termination，episode 预算移除 |
| `El-4090-Confined-Locomotion-Flat_2` | `ConfinedLocomotionRunner` | 64 | 17 / 4 | 训练配置移除 `episode_timeout`，保留 20 s 元数据 |
| `El-4090-Confined-Locomotion-Terrain-Memory_2` | `ConfinedLocomotionRunner` | 64 | 17 / 5 | 训练配置移除 `episode_timeout`，保留地形边界 |
| `El-4090-Confined-Locomotion-Flat-Tripod2-Low_2` | `TripodRunner` | 64 | 19 / 2 | 训练 MDP/奖励，不安装 timeout |

注册 RL 默认均为 `max_iterations=0`，网络或 Adam 构造前拒绝训练。v1/v2/Terrain 使用 24 控制步 rollout；v2 Flat/Terrain 使用 Temporal PPO（5 epochs × 4 minibatches）并在注册默认关闭对称训练；Tripod2 Low 保留 Legacy PPO、LSTM 执行器和独立预算校验。显式 engineering/formal 配方快照一致，P2 未修改任何 PPO 或超参数。

## P2.2 共享 Flat 环境

新增 [`common/flat_env.py`](../../src/hexapod_mjlab/common/flat_env.py)：

- 唯一实现无限平面、机器人实体、reset 事件、本体/上一动作观测、residual PD 动作、通用默认值和显式训练变体；
- `FLAT_GROUND_FRICTION`、`GENERIC_NUM_ENVS`、`GENERIC_EPISODE_LENGTH_S`、`make_flat_env_cfg`、`make_training_env_cfg` 均由这里拥有；
- 不导入任何具体任务包；mjlab 导入放在函数内部，避免本模块作为进程首个导入时触发 mjlab 任务入口点回环；
- 每次调用都创建新的 `SceneCfg`、观测、动作、事件和 reward/termination 字典，不共享可变配置对象。

单平面地形类位于 [`common/flat_terrain.py`](../../src/hexapod_mjlab/common/flat_terrain.py)，仅由共享工厂使用，属于同一 Flat 实现，不是第二个环境实现。

v1/v2 `flat_env_cfg.py` 收敛为任务绑定：

- 保留各自 `TASK_ID`；
- 从 `common.flat_env` 导出 `make_flat_env_cfg` / `make_training_env_cfg` 和既有常量；
- 不再包含 294 行环境构建代码；
- v1/v2 原有测试、Play、Runtime、Checkpoint 和实验脚本的导入路径继续可用。

Terrain 的 `terrain_geometry.py` 与 Tripod 的 `env.py` 直接引用共享工厂，再覆盖各自的地形、接触、执行器、观测或终止语义。

## P2.3 配置与注册清理

- v2 三个任务统一在 [`confined_locomotion_2/__init__.py`](../../src/hexapod_mjlab/tasks/confined_locomotion_2/__init__.py) 注册一次：Flat_2、Terrain Memory_2、Tripod2 Low_2。
- `tripod2_low/__init__.py` 不再在执行导入时注册任务；直接导入该子包时父包先执行，仍会完成一次注册。
- 顶层 `tasks/__init__.py` 只导入 v1 与 v2 包，不再单独导入 Tripod 子包。
- `config/flat_baseline.py` 移除环境工厂与 Play 工厂转发，只保留 Flat Baseline 的显式 RL 配方；`TASK_ID` 由 `flat_env_cfg.py` 单点拥有。
- 删除 v2 未使用的 `IMPLEMENTED` 类变量和模块常量；v1 的 `IMPLEMENTED` 守卫保持原样。
- 更新直接依赖旧导入路径的 GPU 检查与实验脚本；`check_far_shorttrain_gpu.py` 的来源清单加入 `common/flat_env.py`。

最终依赖方向：

```text
hexapod_mjlab.common.flat_env
  ├─ common.flat_terrain（单平面类）
  ├─ common.robot / common.mdp.*
  └─ 无任务包依赖

tasks.confined_locomotion.flat_env_cfg ──> common.flat_env
tasks.confined_locomotion_2.flat_env_cfg ─> common.flat_env

tasks.confined_locomotion_2.config.flat_baseline ─> RL 配方（无环境工厂）
tasks.confined_locomotion_2.config.terrain_memory ─> flat_baseline RL 配方 + terrain_geometry
tasks.confined_locomotion_2.config.terrain_geometry ─> common.flat_env
tasks.confined_locomotion_2.tripod2_low.env ─> common.flat_env + legacy MDP

tasks.confined_locomotion_2.__init__ ─> 注册 Flat_2、Terrain_2、Tripod_2
tasks.confined_locomotion.__init__ ─> 注册 v1 Flat
```

## 尚未解决 / 后续

- P1 遗留的 2048 环境历史 checkpoint 完整恢复仍未在当前 6 GB GPU 验证；P2 未改变该边界。
- 直接以内部 `common.flat_terrain` 或既有 `common.mdp.actions` 作为进程首个导入仍受 mjlab 入口点自动加载顺序影响；官方入口（`import mjlab`、`hexapod_mjlab.tasks`、各任务包）和 `common.flat_env` 已验证无循环。该通用导入顺序不属于 P2 注册问题，本轮未改动。
- 按最新算法决策，v2 Flat Baseline/Terrain Memory 的初始探索标准差 `std=1.0` 是 P2 验收后的独立配方调整，本轮未修改 PPO、动作分布或训练超参数；v1 与 Tripod2 Low 不受影响。
- 按要求暂不进入 P3，不合并回稳定分支。
