## 仍有效的工程结论

- 真实manager转移以每控制步四个物理子步为一个边界。奖励回调共享同一封存的transition record，`dt`只由manager乘一次；逐项非有限值须在任何`nan_to_num`之前捕获并保存故障现场。
- 正常timeout final observation必须在reset前封存；termination和truncation是分开存储的flag。timeout bootstrap使用自然final observation，不用reset observation，GAE不跨episode。部分reset仅修改选中环境；未选行的物理持久字段、warmstart、窗口、标签、动作/命令与噪声身份保持，选中行用真实T1 reset并先取得唯一首扫描。
- scan时钟独立于episode clock。近端只保存新扫描，远端10槽来自10个不同新扫描；连续缺口/扰动时钟在部分reset时不重置。source ID、原方向、有效mask与角键跟随raw ray来源，不从加噪或饱和后的点倒推身份。
- 训练故障保存NON_RESUMABLE现场并冻结整次运行；工程自然跌倒和formal done保存后停止。只有隔离且带身份的`training_lifecycle_fixture`用于部分reset协议测试，不可冒充自然采集。Play中按确认跌倒门保存场景并暂停，故障永久冻结，碰撞继续，不触发20秒truncation。
- PPO从同一采集前向数据更新，参数按ID去重后只进入一个Adam；一个联合loss、一次backward、一次全参数裁剪。地面loss先帧内有效位置平均，再按真实独立扫描平均；镜像样本不能增加扫描分母。

## checkpoint与严格重放

当前完整训练checkpoint schema为`confined_locomotion.checkpoint/v3`；稳定保存边界是上一更新结束、rollout已消费清空、下一动作前。完整加载必须先核对source、compiled model、依赖、device、完整grid identity和mode，并验证全部checkpoint section，再修改运行状态。全状态含物理持久数组、env/runtime生命周期、窗口/缓存、噪声与PRNG、optimizer/LR和计数器；加载后只允许一次派生状态forward，不得reset、积分、scan或抽随机数。上一步奖励缓存是payload-only诊断，加载不应用；其原始差异单列保存，下一个控制身份重新生成缓存，不影响因果续跑。跨进程地址只作原始诊断，全部物理内容与storage形状/类型严格比较。历史源码checkpoint不能直接用于当前完整续跑；本任务两份旧归档已删除，不再提供其完整重放包。当前源码变化仍不放宽完整续跑identity。

P5曾以不同新物理rollout要求严格下一次更新逐位相同，真实检查为FAIL；该失败仍是历史结果。当前可要求位级相等的是同一已保存真实rollout在连续分支和恢复分支上的Adam/权重更新重放。恢复后另采新24步、完成实际更新用来证明可继续运行；不承诺新物理rollout、长期轨迹或跨设备逐位相等。保存/加载失败的中间optimizer现场不是稳定checkpoint。

任务play无论输入full还是weights checkpoint，都按**仅权重**模式加载网络状态；它不恢复训练physics、Adam、PRNG、命令、episode或采样分布，不是训练续跑。mean-only play不用分布provider或optimizer。通用mjlab play不支持该任务。

## 已验证的CLI用法

本文整理时以实际入口的`--help`核对以下命令，两个任务CLI均exit 0；`tests/run.py --help`也确认`confined_cpu`和`confined_gpu` profile存在。任务train/play CLI仅核对help；本文的真实工程见证由GPU检查入口执行并保留完整命令。

```bash
conda run --no-capture-output -n hp_mjlab python tests/run.py --profile confined_cpu
conda run --no-capture-output -n hp_mjlab python tests/run.py --profile confined_gpu --list
conda run --no-capture-output -n hp_mjlab python scripts/experiments/confined_locomotion/train.py --help
conda run --no-capture-output -n hp_mjlab python scripts/experiments/confined_locomotion/play.py --help
```

`train.py`要求`--seed`、`--num-envs`、`--max-iterations`、有序`--grid-x`和`--grid-y`；`--parallel-tol`默认`1e-6`。`--engineering-validation`仅授权最多2环境、恰好1次更新的真实训练模式检查。该入口受配方与设备限制，不提供未知最终网格或正式预算。

`play.py`要求显式`--checkpoint`、全新`--output`、有序grid x/y；支持`--parallel-tol`（默认`1e-6`）、手动`--vx/--vy/--wz`及明确的观察扰动preset。它在创建环境之前按完整grid身份检查checkpoint；illegal手动命令零状态变更。默认创建仅绑定`127.0.0.1`的本地Viser viewer并启动暂停；`--no-viewer`关闭viewer，但必须同时指定`--start-running`以无界面运行。默认不自动random-resample指令，也不触发20秒reset；跌倒保存后暂停，故障冻结，碰撞继续。CLI存在本身不作为GPU或学习效果证据，实际工程门见上文。

运行任何实际检查时使用新的输出目录并保留原始stderr/stdout、完整失败和配方；勿复用既有run目录。历史P9条目不能替代当前源码工程门。
