## 必须修复的发现

### R1 / P1：评测器允许假成功，早终止还会中断整批统计

定位：`scripts/tools/t0/eval_episodes.py:69–133,225–257,298–365`。

- 高度使用`abs(mean(z)-h)`，±0.10m偏差相互抵消后通过0.05m门；应按测区最大绝对误差验收。
- 侧移使用带符号的最终值直接比较≤0.30m。负方向偏移5m仍通过；也未检查过程中的最大偏移。
- 站立只比较测区首尾位置。测区内离开2m后返回，仍通过0.05m门。
- 请求0.25m/s、实际0.35m/s的非零错误指令没有被单episode验证器拒绝；仅“是否全部置零”的检查不足。当前真实记录另有指令一致性门，不能用它代替重算器自身的验证。
- 安全门直接相信`any_violation`。同一输入中非足/自碰/NaN计数为正、该布尔量为false时仍PASS；应从原始记录重算并拒绝不一致元数据。
- 真实1秒早终止的50帧输入在空测区上`.max()`，抛`ValueError`。既有“截断反例”保留完整数组，因此没有覆盖实际早终止路径。
- `env.step()`使用自动reset，返回的终止帧状态已经复位；随后才记录根位姿等，丢失真实终止状态。安装诊断器能保留部分接触事件，不等于完整终止轨迹保存。
- reset后强制改command，但首次actor输入仍是旧reset观测；应重新计算该观测。`--num-envs 16`只生成每指令16条却仍可能PASS，训练OOM降至16不允许减少评测32条/指令。
- episode没有保存完整的200Hz裁剪/警告等安全累积记录；50Hz施加力矩不足以证明全物理步门。

实际调用原验证器的反例见`validator_probes.json`：上述侧移、高度、站立返回、错误非零指令、矛盾安全计数均被错误判为PASS，1秒截断抛异常；物理单位正确的正常前进正例能通过。测试里的合成前进正例另漏乘0.02s，20秒位移约225m，需改成与速度一致的样本。

修复要求：明确测区参考点和逐帧最大偏移，逐帧核对实际command，校验字段、长度、有限性和安全记录一致性；所有早终止包括0帧/settle内终止都应产出完整FAIL及原因，而非中断整批。终止前状态和安全事件必须保存；每指令固定32个episode，不随批大小改变。

### R2 / P1：质心质量索引错位，静态支撑判定不可采信

定位：`scripts/tools/t0/hold_gate.py:184–205`。

实体数组包含29个机器人body；实际编译模型body 0是world，body 1是terrain，机器人从body 2开始。代码用`masses[1:1+robot_body_count]`给机器人COM加权，质量错配一位。总质量恰好仍相同，不能由总质量检查发现。

用原run的`env_model.mjb`与完整T1见证复算：真实COM为`[0.00535,-0.00626,0.24325]m`，错误方法为`[0.11821,-0.04004,0.19898]m`，三维偏差0.12585m；同一足原点凸包的裕度分别0.44428m和0.33132m。这里是见证构型的反例，不把它冒称为原5秒末态裕度的精确修正值。证据见`com_alignment.json`、`static_probes.json`。

此外，关节RMSE先在18关节间求平均、漂移只看最终值，不是T1的逐关节最坏跟踪/过程漂移协议；数值角度边界`[-π,π]`、完整警告及静态支撑/平衡检查没有完整继承，原保持时间序列不足以独立重算全部门。

修复要求：按实际body ID映射质量或使用可信subtree COM，核对实体和host索引；支撑域优先使用真实承力接触位置。逐项对应T1保持协议，保存时间序列和最坏环境/时刻，保留64N·m名义余量诊断与80N·m仿真裁剪上限的区别。

### R3 / P1：GPU异常漏检，诊断器并非只读

定位：`src/hexapod_mjlab/tasks/el_4090_lidar/t0/diagnostics.py:155–161,236–241`；`scripts/tools/t0/contact_gate.py:408–415`。

有限性只检查根位置、关节位置/速度，未覆盖根速度、四元数及相关动力学输入。实际GPU注入根qvel的NaN，诊断累计仍为0。

当前mujoco-warp虽没有经典`mjWARNING`结构，却提供`wp_data.overflow`。实际深穿透反例产生hfield位32且接触被截断；有限数值不能代表没有物理异常。原`physics_warning_surface`无条件PASS，未读取这个可用信号，现有episode也缺少相应记录。深穿透反例同时有非足接触，因此本审查不声称它让整个episode安全门假通过；它证明警告漏检。

诊断器在每物理子步对正在运行的环境额外调用`sim.forward()`。GPU实测同一已积分qpos/qvel保持不变，但qacc、约束力、sensor数据分别最大改变40.3374、5.4802、5.4735；它改写了之后奖励/终止可能读取的缓冲，与方案“状态查询不得改写正在运行环境”冲突。训练没有安装此hook，评测和保持安装了它，时序协议不一致。

同seed的两次8环境5秒运行也有轨迹/奖励差异，但GPU浮点非确定性存在，不能把全部差异归因于hook。两次尾段关节速度都约0.093rad/s、仍失败，因此保持失败不是仅关掉诊断器就能解决。证据见`overflow_probe.json`、`diagnostics_probe.json`和`diagnostics_trajectories.npz`。

修复要求：全面记录实际GPU警告/overflow和状态有限性，任何容量溢出使相应安全结论无效。采用不改运行缓冲的观察或独立scratch重建，明确物理步和终止前覆盖；如确需改变任务求解时序，必须显式统一训练/评测协议并重新验证，不能继续称为只读查询。

### R4 / P1：重放身份门没有验证源码、模型与原始数据身份

定位：`scripts/tools/t0/replay_verify.py:86–106`；`scripts/tools/t0/run_acceptance.py`源码快照生成逻辑。

重放器虽计算当前源码/资产SHA，但`identity_ok`只由checkpoint与summary中的SHA比较更新，没有将源码/模型哈希与冻结清单比对，也未验证缺失文件、resolved config、episodes或summary身份。反例把仓库根指向仅含替换诊断源码、没有模型/其余源码的临时目录，原checkpoint不变，“identity_recomputed”仍PASS（n_files=2）。该探针的完整重放因sandbox没有CUDA返回1；证明的是身份门错误PASS，不声称完整重放返回0。

源码快照在所有阶段结束后才保存，缺少前后身份一致性的强制检查；源码副本包含XML/URDF但没有其引用的STL副本。模型二进制和基线资产SHA是有价值的冻结材料，重放器目前没有真正利用它们完成可靠核验。

修复要求：运行前固定完整预期文件集合与SHA，运行后再比对；缺失、额外替换、配置/输入/模型改变都应明确FAIL。使用完整资产副本或不可变可靠引用，精确关联编译模型、源码、依赖和数据；summary核对原始数据身份后再独立重算。证据见`identity_probe.stdout.txt`和`tampered_identity_replay/replay_verify.json`。

本次另外独立核对确认当前文件确与原快照一致；身份门有缺陷不等于当前产物被篡改。

### R5 / P2：默认关节offset镜像测试证明了错误的等式

定位：`scripts/tools/t0/contract_gate.py:483–498`及`tests/t0/test_units.py`。

测试证明`P(q-d)=Pq-Pd`，人为把默认offset也交换了。但同一任务镜像后的机器人仍使用固定默认offset d，需要验证`Pq-d`以及绝对动作目标`P(d+s·a)`。T1见证的左右目标不完全相等，实际误差最大0.001216rad；动作scale=0.25时需要最大0.004865的offset修正。当前纯置换镜像没有这项任务适配。

这是小但确定的契约错误，不据此推断训练一定失效。修复应放T0任务内、保持旧任务和共享网络默认行为，覆盖相对观测、动作及历史动作语义；用物理绝对姿态/动作目标正例验证，而非仅两次镜像恢复。证据见`validator_probes.json`的`mirror_offset`。

### R6 / P2：CPU独立自碰复核把足地接触当作自碰

定位：`scripts/tools/t0/contact_gate.py:332–340`。

`any(a != b for a,b in distinct_body_pairs)`将world-foot也计为自碰。正常站立CPU反例只有6对world-foot、没有任何机器人内部接触，这个predicate却为true。HIP复核也应检查HIP与terrain，不能以任意含HIP的body pair替代。CPU重建使用plane，还需明确与GPU同源hfield模型的差别。

原GPU折叠构型确实记录了机器人自碰；本发现否定的是“独立CPU确认”方法。修复应按机器人/地形域和实际body/geom ID分类，并在同源模型、记录的qpos/qvel上复核。证据见`static_probes.json`。

### R7 / P2：总验收、预算和状态检查不足以阻止缺门与越预算

定位：`scripts/tools/t0/run_acceptance.py:40–50,211–216`；`train_short.py:221–250`；`t0lib.py:39,147–159`。

- 总验收只判断已运行阶段里有没有失败，未要求所有必需阶段存在；audit不在必需清单，`--skip-regression`缺gate_a/b仍可能整体PASS。
- 保持/诊断门失败后仍继续训练，违反“诊断通过再训练”的前提。本次原run明确失败并非吞错，但准入顺序未落实。
- 训练CLI允许任意迭代数、seed与环境数；`within_frozen_budget`只写证据，不参与PASS。比如32×24×6会超过3,840步却仍可判完成；实际交付的32×24×5没有超预算。aux/symmetry是否存在也只报告，未纳入门。
- 状态聚合只拒绝FAIL/NOT_VERIFIED，BLOCKED、PARTIAL或错误状态名可能被当作通过；科学JSON也应拒绝NaN，记录缺字段/非法状态。

修复要求：固定必需门及输入预算，不允许省略或不识别状态；准备失败后下游标为未执行/未验证，返回非0；预算、seed、配置、损失项等都参与严格判定。独占目录对配置、checkpoint等产物同样生效，不只是最终阶段JSON禁止覆盖。

## 保持失败与归因边界

原32环境5秒尾段关节速度0.0937rad/s超过冻结0.05rad/s，**继续保留FAIL，不放宽验收线**。原warp CPU/GPU、经典MuJoCo hfield/plane差分支持“地形接触表示或对应求解设置值得优先排查”。但不同模型间的求解器、接触/摩擦参数等未被完整控制，部分柱场值为脚本硬编码，不能断言已经严格证明hfield离散采样是唯一原因。

后续优先做同源模型、同参数仅替换地形表示的受控试验；T0可采用任务内plane/mesh最小适配，但必须重新验证物理/raycast/监督的一致性和测区边界。诊断器修复后再按原T1协议测试真实静止，不能为了前进训练先放过这一门。

## 修复与再次验收顺序

1. 先修只读物理诊断、完整异常/子步记录、正确body映射和真实接触复核；保存终止前状态与保持轨迹。
2. 修严格评测与镜像offset；新增本报告反例及正常正例，覆盖早终止、负侧移、返回原点、均值抵消、元数据矛盾和局部reset。
3. 固定身份清单、预算、必需门和状态聚合；源码/资产/数据/配置修改或缺失反例必须失败。
4. 用受控地形实验修静态保持，保持原阈值和碰撞过滤；通过准备门后才执行原短预算训练及64 episode评测。新增运行独占目录，不覆盖本轮失败证据。
5. 再做独立审查，全部T0-A必需门通过后，另定T0-B长训练预算。本轮前进0/32不是T0-A额外失败项，也不是扩大训练预算的理由。

这是修复建议与准入要求，不是本次已经实施的优化。T1既有分层验收结论继续有效；T0-A修复完成前，不扩展到新联合任务或整个mjlab架构。
