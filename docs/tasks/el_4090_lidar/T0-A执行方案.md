# T0-A：实际基线审计与平地训练、评测管线

2026-10-03。下一轮建议执行范围，尚未实施。本文件是本轮交给GLM的唯一执行方案；用户启动GLM后，先实施T0-A，再由Codex审查。通过后另行启动T0-B正式学习行走验收，不能将T0-A短训练成功写成T0全部完成。

## 为什么先做这一轮

[T1](../../research/morphology/形态可达性测量.md)已经获得35个保持和7个脚本慢速运动构型，但crawl平均指令速度仅0.0025m/s，控制器使用真值、IK和接触力规划。它不能代替现有LiDAR/PPO策略的平地行走验证。

对主工作区实际代码的阅读发现以下待核实项；这里区分事实与影响推断，不直接判定全部是bug：

| 位置与事实 | 这一轮需要处理的问题 |
|---|---|
| 环境已加载`el_4090_lidar.xml`，默认18关节全0、根高0.50m | 以实际带LiDAR模型为基线，核对默认姿态与T1见证、运行时约束的关系 |
| `mdp/rewards.py`固定`BASE_HEIGHT_TARGET=0.25` | 与T1已验证体高不一致；审查奖励是否把策略推向碰撞/不可保持姿态 |
| 惩罚接触sensor只包含BASE、SHANK、THIGH；跌倒终止为重力z>−0.1或世界z<0.12m | HIP和其他非足碰撞件需独立检测；旧终止通过不代表没有危险接触 |
| 模型名义位置限位仍有效，奖励读取soft limits | 不把URDF限制当硬件真值，也不把T1单关节局部扫描区间当全局限位 |
| 指令deadzone=0.20m/s，启用heading转换和命令课程 | 不用0.1m/s之类已被置零的指令声称跟踪成功；记录实际送入策略的指令 |
| play仅去噪声、push、课程，质量/摩擦startup随机化和reset扰动仍可能保留 | 需要独立确定性评测配置，不能认为play天然无随机化 |
| LiDAR和高度监督依赖`El4090PillarFieldCfg`及terrain view | 换平地必须让物理、raycast与高度真值一致，不能只换碰撞平面却扫描旧柱场 |
| actor的GRU沿点序列运行，`is_recurrent=False` | 保留当前网络契约；不在本轮改成跨控制时刻循环PPO |
| 主目录现有两组checkpoint仅发现`model_0.pt`、`model_1.pt` | 核对内容、迭代和来源后分类，不假定它们是成熟行走策略 |
| `scripts/bench/run_baseline_mjlab.sh`根路径只回退一级，且训练命令带`|| true` | 不直接当严格验收入口；新入口正确确定仓库根路径、传播失败、准确绑定run目录 |

历史基准记录为RTX4050 6GB、32环境约6.6秒/迭代；只是旧配置测量，不保证本轮吞吐。新执行者先检查当前CUDA、安装来源与可用显存。默认4096环境面向另一硬件，本轮不可直接使用。

## 实施顺序

### 1. 审计和冻结实际输入

读取仓库规则、总体方案、T1当前报告/库、实际任务配置、奖励/动作/指令/终止/地形/LiDAR/runner及相关旧门。列出主目录已有修改，保留原始SHA。记录Git HEAD和dirty清单、Python模块实际`__file__`、依赖、模型/mesh SHA、传感器mount、关节/动作/执行器顺序与单位、控制50Hz/物理200Hz/LiDAR10Hz，以及名义限位、reward/curriculum/DR对基线的影响。

checkpoint目录、iter、配置、模型结构、来源和文件SHA全部登记。兼容不等于学会行走；来源不明或迭代不足要标注未知/短管线证据，不选最高文件编号就称最佳策略。

### 2. 建立隔离、确定性的平地配置

只做平地，无外推力、质量/摩擦随机化、初始化根速度、观测噪声、奖励阶段切换或指令课程；训练可保留原PPO动作探索，评测使用确定性actor。固定μ=1.0、kp=130、kd=2、裁剪80N·m，明确属于仿真假设。现有点云维数2754、height_grid187、动作18和网络含义保持不变。

从T1 `height_0.48_width_1.00`完整见证初始化，包括关节目标/实际根高/四元数的区分；按实际足底距离抬起至少1mm再落地，不硬编码足原点清地。临时高度目标应从该见证的实际保持高度读取（当前约0.459859m），配置可显式覆盖；它是T0平地调试参考，**不定稿论文z₀，也不是0.48m名字所对应的精确末态**。同一高度语义用于奖励和评测。

名义限位策略单独显式化：T0实验模型可在任务加载的内存spec中关闭18个铰链名义位置限位，与T1测量假设一致，保持资产字节不变、现有task不变；对应旧soft-position-limit惩罚必须显式禁用或从本轮奖励移除，不能继续惩罚未标定URDF值。保留数值越界诊断`[-π,π]`及真实碰撞门，但不宣传这是机械安全区间或利用放开限位来隐藏碰撞。

平地推荐沿用现有terrain builder/view链路，使用不生成柱体的任务专用配置；验证物理高度、LiDAR命中和height_grid目标确实来自同一平地，测区外/未命中有明确语义。若实现其他最小平地adapter，必须满足相同一致性检查，不构建T2通用三维场景框架。检查真实自遮挡，若当前raycast只含terrain而不含机器人，明确记录能力缺失，本轮不冒称已支持，也不临时实现完整机器人raycast管线。

训练指令先限于站立和前进：显式站立比例0.20，其余vx∈[0.25,0.35]m/s，vy=0、yaw_rate=0；禁用heading转换或证明其始终给出零偏航指令。每episode固定指令，独立评测仅用vx=0和0.25m/s。不要用teacher关节轨迹替代PPO动作，也不要加入根部执行器/外力。奖励调整只解决有证据的基线冲突，不一次重写全部奖励。

### 3. 诊断和反例门

必须检测HIP及全部实际非FOOT碰撞件触地、允许碰撞过滤后的真实自碰、有限状态、物理警告、接触足、体高/倾角、动作目标/施加力矩、力矩裁剪比例。记录碰撞被模型父子/焊接排除的边界。不能只读原`penalised_contact`总和，也不能只在控制帧检查后宣称覆盖200Hz全过程；优先在4个物理子步都累积接触事件，做不到时标明采样盲区并将对应全过程门列为未通过。

用实际诊断器验证：正常FOOT接触允许；人为HIP/非足触地、自碰、悬空、NaN/警告、局部reset分别触发正确状态。不要仅注入假的汇总统计来证明碰撞sensor有效。状态查询不得改写正在运行的环境；CPU离线重建应来自记录的实际qpos/qvel与同源模型，不拿参考目标构型替代真实状态。

确定性零动作PD保持32环境×5秒：报告实际碰撞、根漂移/姿态、真实足支撑、关节跟踪、末段静止和力矩需求，关键阈值沿用T1保持协议。若GPU/CPU接触求解差异导致失败，保留反例和差异分析，不能为了PASS放宽门或改碰撞过滤。零动作表示目标偏移为0、PD仍在工作，不是所有关节力矩为0。

接着验证局部reset不串环境、mount与镜像一致、平地观测/监督有限且维数正确、50/10Hz时钟正确、站立/前进实际command正确。初始化/动作默认关节offset变化时，核查镜像对绝对关节姿态和相对观测/动作的转换；镜像两次恢复原值不等于物理左右等变。必要适配放本任务内并保持旧默认行为，不能忽略offset变化或静默关掉镜像损失来通过。平地不要求柱场专用的hit率条件，旧Gate B的柱场断言不能盲目搬用。旧task针对受影响路径运行必要回归；不要无条件重跑全部历史长训练。

### 4. 短PPO管线与独立评测

CUDA可用且诊断门通过后，**32环境×24步/迭代×5迭代、seed=1，最多3,840个环境控制步**；保存checkpoint，检查PPO/aux/mirror/梯度与优化器更新有限、参数确实改变、训练恢复与确定性reload前向一致。CPU模式、dummy训练或既有checkpoint加载均不能替代这一真实环境训练门。

遇到显存不足只可用16环境（步预算变为1,920），记录原因和实际预算；不得缩小点云/网络/关闭真实雷达来偷换任务。训练管线最多20分钟墙钟预算，含编译；超过则完整保存日志并标为NOT_VERIFIED。不能扩大到几百迭代、循环改种子或连续调参直到出现成功录像。

评测每个command32个episode、各20秒，reset种子固定1001–1032（两种command共64个episode），从同一初始化协议开始，使用与训练seed独立的数据。前2秒作为settle，18秒作为测区；全episode保留安全事件。记录原始episode身份、请求/实际command、姿态、真实速度、位移、碰撞、termination与timeout、力矩/clip、脚接触与滑动诊断；早终止视为失败，不能auto-reset后将多次尝试拼成一条成功episode。实际执行步数及settle/测区计数入清单。

评测入口可测试短checkpoint，但它**不要求短训练已学会行走**；如实给出步行FAIL/NOT_VERIFIED。另用“完全静止却要求前进”“途中跌倒/非足接触”“未完成episode”“请求指令被置零”反例检验统计器不会误报成功。反例可作用于已保存轨迹和统计器；接触获取器的真实物理反例仍须单独通过。

为T0-B实现并冻结最小验收定义：完整20秒、无非足/自碰与物理异常；测区倾角≤15°、体高误差≤0.05m；前进沿初始化heading轴位移≥3.0m、身体vx对实际0.25m/s指令MAE≤0.10m/s、侧向漂移≤0.30m；站立测区位移≤0.05m；实际施加|τ|≤80N·m。64N·m只作为T1名义余量诊断，不冒称已标定硬件限值；饱和比例、支撑/滑足、关节速度与角度需求完整报告。任何阈值均是本轮声明的仿真协议，不是已批准的论文指标或电机规格。

步行允许动态支撑切换，不套用T1 crawl的“全程至少4足与静态COM余量≥3cm”。零动作静态保持仍使用T1支撑门。滑足若测的是FOOT body原点速度，名称与解释必须如实，不能冒称接触点无滑移。

T0-B未来要求两种command各至少29/32通过（≥90%）；本轮只验证评测器与生成真实失败分母，不以这个步行比例阻碍T0-A管线交付，也不写“稳定行走已通过”。多训练seed及扰动/转向评价留后续，不将单种子准备基线当论文结论。
