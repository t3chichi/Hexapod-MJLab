# 新机器部署

本页用于在Linux NVIDIA训练机获取当前Flat Baseline与Terrain Memory代码并配置环境。当前发布分支为 `main`；旧 `confined-flat-2-pretrain-v1` tag仅对应此前平地版本，不包含后续Terrain Memory及当前性能优化。

> 本轮修复仅在本地 `refactor/project-architecture`，尚未推送或合并 main。以下克隆命令获取已发布版本；部署本轮修复需先取得最终验收的 commit/tag，并核对实际 HEAD，不能仅凭分支名称推断版本。

## 获取代码

```bash
git clone --branch main --single-branch \
  https://github.com/t3chichi/Hexapod-MJLab.git
cd Hexapod-MJLab
git rev-parse HEAD
git status --short
```

已有该分支的干净检出可执行 `git pull --ff-only`。开始一次训练前记录commit；严格续训保留该版本，不在运行中更新源码。

机器人MJCF/URDF/网格、固定雷达catalog与selection均随仓库提供；默认Heightfield由代码生成。无需复制开发机的 `logs/`、性能工作树、缓存、checkpoint或本地conda目录。仓库不附训练好的模型，Play需使用自己训练的checkpoint。

## 安装环境

先安装conda并确认 `nvidia-smi` 能识别GPU。然后执行：

```bash
conda env create -f environment.yml
conda activate hp_mjlab
python -m pip install -e .
python -m pip check
```

`environment.yml`固定Python和主要依赖发行版本；`pyproject.toml`维护包依赖及资源声明。采用editable安装以保留任务脚本、测试和源码的仓库布局。已有同名但不同依赖的环境时，应使用独立环境，避免直接覆盖正在使用的训练环境。

安装后核对实际PyTorch/CUDA及GPU执行：

```bash
python - <<'PY'
import torch
print('PyTorch:', torch.__version__)
print('CUDA runtime:', torch.version.cuda)
assert torch.cuda.is_available(), 'CUDA unavailable'
print('GPU:', torch.cuda.get_device_name(0))
print('Capability:', torch.cuda.get_device_capability(0))
x = torch.ones((32, 32), device='cuda')
print('CUDA matmul:', float((x @ x)[0, 0]))
PY

python -B scripts/experiments/confined_locomotion_2/train.py --help
python -B scripts/experiments/confined_locomotion_2/train_terrain_memory.py --help
```

开发机使用的PyTorch构建为2.11.0+cu130，CUDA runtime为13.0；这不等于目标机器已验证。若驱动或wheel与5090不匹配，依据[PyTorch官方安装说明](https://pytorch.org/get-started/locally/)选择匹配构建，并记录实际依赖。不要仅根据系统CUDA toolkit版本判断所装PyTorch可用性。

## 启动任务

先按[测试说明](../../../../tests/confined_locomotion_2/README.md)完成CPU及有限GPU检查，再按[快速开始](../../../../src/hexapod_mjlab/tasks/confined_locomotion_2/快速开始.md)运行Flat或Terrain训练。测试配方、checker命令及打包检查统一在测试目录维护，不作为日常训练配方。

当前稀疏训练候选为near×6/far×10、hit10；默认执行模式为 `low_memory`，点GRU重放上限1024，采集上限128。5090上的环境数、批量与吞吐尚需实际测量，测量方法见[实验工具](../../../../scripts/experiments/confined_locomotion_2/README.md)。

完整恢复要求物理签名、配方、环境数和状态兼容，不以源码位置、commit或GPU型号门控；缺少新物理签名的旧文件仅可用于符合条件的 weights-only Play。4050→5090完整恢复和目标机容量尚未实测，不应把不设设备硬门解释成迁移已经验收。目标机先做有限检查，再决定从零训练或使用已验证兼容的新checkpoint。实际规则及代码版本记录见[监控与保存](监控与保存.md)。
