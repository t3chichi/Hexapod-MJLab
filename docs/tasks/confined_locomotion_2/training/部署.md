# 新机器部署

本页用于在Linux NVIDIA训练机获取当前Flat Baseline、Terrain Memory与Tripod2 Low代码并配置环境。当前发布分支为 `main`；旧 `confined-flat-2-pretrain-v1` tag仅对应此前平地版本，不包含后续Terrain Memory及当前性能优化。

> 本轮修复仅在本地 `refactor/project-architecture`，尚未推送或合并 main。以下克隆命令获取已发布版本；部署本轮修复需先取得最终验收的 commit/tag，并核对实际 HEAD，不能仅凭分支名称推断版本。

## 获取代码

```bash
git clone --branch main --single-branch \
  https://github.com/t3chichi/Hexapod-MJLab.git
cd Hexapod-MJLab
git rev-parse HEAD
git status --short
```

已有该分支的干净检出可执行 `git pull --ff-only`。开始一次训练前记录commit；严格续训保留该版本，不在运行中更新源码。

机器人MJCF/URDF/网格、固定雷达catalog与selection均随仓库提供；默认Heightfield由代码生成。无需复制开发机的 `logs/`、性能工作树、缓存、checkpoint或本地conda目录。仓库不附训练好的模型，Play需使用自己训练的checkpoint。

## 安装环境

新机器首次安装时，先安装conda并确认 `nvidia-smi` 能识别GPU，再执行以下命令。已有 `hp_mjlab` 环境时先核对解释器及依赖，跳过创建环境；不要自动新建uv/venv替代环境或升级、重装训练依赖。

```bash
conda env create -f environment.yml
conda activate hp_mjlab
python -m pip install -e .
python -m pip check
```

`environment.yml`固定Python和主要依赖发行版本；`pyproject.toml`维护包依赖及资源声明。采用editable安装以保留任务脚本、测试和源码的仓库布局。已有同名但不同依赖的环境时，先记录差异并明确环境变更方案，不能直接覆盖正在使用的训练环境；自动化代理执行环境变更须获得用户明确授权。

安装后核对实际PyTorch/CUDA及GPU执行：

```bash
python - <<'PY'
import sys
import torch
print('Python:', sys.executable)
print('PyTorch:', torch.__version__)
print('CUDA runtime:', torch.version.cuda)
assert torch.cuda.is_available(), 'CUDA unavailable'
print('GPU:', torch.cuda.get_device_name(0))
print('Capability:', torch.cuda.get_device_capability(0))
x = torch.ones((32, 32), device='cuda')
print('CUDA matmul:', float((x @ x)[0, 0]))
PY

python -B scripts/experiments/confined_locomotion_2/train.py --help
python -B scripts/experiments/confined_locomotion_2/train_terrain_memory.py --help
```

开发机使用的PyTorch构建为2.11.0+cu130，CUDA runtime为13.0；这不等于目标机器已验证。若驱动或wheel与5090不匹配，依据[PyTorch官方安装说明](https://pytorch.org/get-started/locally/)选择匹配构建，并记录实际依赖。不要仅根据系统CUDA toolkit版本判断所装PyTorch可用性。

## 启动任务

先按[测试说明](../../../../tests/confined_locomotion_2/README.md)完成CPU及有限GPU检查，再按[快速开始](../../../../src/hexapod_mjlab/tasks/confined_locomotion_2/快速开始.md)运行Flat、Terrain或Tripod训练。测试配方、checker命令及打包检查统一在测试目录维护，不作为日常训练配方。

Flat v2、Terrain和Tripod新训练默认稀疏near×6/far×10、hit10；默认执行模式为 `low_memory`，点GRU重放上限1024，可通过 `--point-replay-chunk 256` 或128显式缩小，采集上限仍为128。5090上的环境数、批量与吞吐尚需实际测量，测量方法见[实验工具](../../../../scripts/experiments/confined_locomotion_2/README.md)。

Play默认使用本机原生MuJoCo passive窗口，不提供网页端口参数。远程网页调试请运行 `debug_flat.py` 或 `debug_terrain_memory.py` 并加 `--no-native --port 8096`，然后转发该端口：

```bash
ssh -L 8096:127.0.0.1:8096 用户名@训练机
```

`debug_*` 默认也会启动原生窗口；远程无桌面环境使用 `--no-native`，`--no-viewer`则关闭全部界面。键位与网页快照行为见[任务说明](../README.md#可视化与模型边界)。

完整恢复要求物理签名、配方、环境数和状态兼容；v2任务还要求`temporal_ppo/v2`及Recipe中的`ppo_semantics`身份。源码位置、commit或GPU型号不门控恢复；缺少物理/PPO身份的旧文件仅可在任务、架构和sampling相符时用于weights-only Play。不会迁移旧Adam状态或声称旧更新等价。4050→5090完整恢复和目标机容量尚未实测，不应把不设设备硬门解释成迁移已经验收。目标机先做有限检查，再决定从零训练或使用已验证兼容的新checkpoint。实际规则及代码版本记录见[监控与保存](监控与保存.md)。

## 旧版本

`confined-flat-2-pretrain-v1`仅对应2026-10-24平地交付版本。需要复现该历史版本时使用[旧部署与基线](部署与基线.md)及其冻结证据；当前部署无需使用该tag或复制其本地日志。
