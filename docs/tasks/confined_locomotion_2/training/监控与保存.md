# 训练监控与保存

本页维护Flat Baseline和Terrain Memory的指标、保存及恢复语义。运行命令见[快速开始](../../../../src/hexapod_mjlab/tasks/confined_locomotion_2/快速开始.md)，安装见[部署](部署.md)，测试步骤见[测试说明](../../../../tests/confined_locomotion_2/README.md)。

## 入口与生命周期

三个任务的项目训练入口均调用 MJLab 原生 `launch_training` / `run_train`，由官方选择GPU、创建时间戳日志目录、保存 `params/env.yaml` 与 `params/agent.yaml`、构建环境和注册的Runner，并通过官方本地查找机制定位续训文件。项目入口保留显式训练预算、任务配方预检和完整Checkpoint验证，不另建启动器。不同任务既有seed初始化顺序及FP32/TF32设置保留，不以统一入口为由重排随机数调用。

Logger与官方Runner一致，在 `learn()` 开始时初始化writer，使构造之后登记的源码仓库也进入官方代码记录；同一Runner再次调用 `learn()`复用writer。非Git安装的MJLab/RSL-RL会由官方提示跳过对应Git记录，不能将其视为依赖源码快照已保存。

Runner构造失败或进入训练后的异常（含writer初始化失败）会尝试释放已持有的Runtime、环境和writer；诊断写入或清理错误不会替代最初异常。正常结束仍通过官方 `env.close()`释放资源。当前MJLab入口在Runner之外没有统一的 `finally`，因此Runner构造之前、或外部 `runner.load()`预检拒绝等路径不在上述自动清理范围；进程内直接调用应由调用方用 `finally`关闭环境/Runner。恢复预检拒绝仍不主动关闭或修改可继续使用的Runner。

## 周期保存

默认 `save_interval=50`，在累计完成第50、100、150……轮PPO后的稳定边界保存 `checkpoint_full_000050.pt` 等完整文件。每轮为24步采集、5 epochs×4 minibatches，不是每50个控制步保存一次。从75轮恢复后，下次周期保存仍在100轮。

正常结束生成 `final_checkpoint_full_XXXXXX.pt`。若结束轮次恰逢周期保存，两文件以硬链接复用内容。文件不覆盖、不自动删除；需自行安排日志盘空间。中断或故障不保存半轮更新，从最近成功写入的完整文件恢复。

完整文件包含网络、Adam、原始/镜像GRU历史、环境、扫描、命令、扰动、随机流及未结束episode的累计指标。Logger 最近100个已完成episode的可选滚动窗口另存于 `learning_metrics`，不取代既有未结束episode累计张量。没有该窗口的旧checkpoint仍可完整恢复：未结束episode累计照常恢复，Logger滚动窗口从空开始。Runtime当前动作前输入缓存及窗口快照随Runtime状态保存；PPO的临时重放计划、packed准备数据和Collector的网络特征缓存不写入checkpoint，恢复后按需重建。

`--save-interval`接受正整数，作为运行记录保留，续训可显式调整。`--iterations`表示本次新增轮数；保存名使用累计完成轮数N，TensorBoard迭代横轴使用累计索引N−1。

## 严格续训与Play

完整恢复比较架构、编译模型结构、物理签名、动作/PD、奖励权重、终止语义、仿真步长、训练配方、种子、环境数、扫描身份和状态张量；Terrain还校验高度网格与损失权重，Tripod还校验执行器资产哈希与legacy奖励阶段。源码路径、版本元数据、设备型号、执行模式和保存间隔不作为恢复硬条件。切换 `low_memory/speed` 只改变激活重计算方式；相同selection内容换路径不改变扫描身份。

物理签名 schema 为 `hexapod_mjlab.model_physics/v1`，比较名义 MuJoCo 模型及实际 Warp 静态模型的数值内容，涵盖质量/惯量、关节/阻尼、碰撞几何与接触、执行器、地形和物理选项；不比较文件路径、视觉材质或编译二进制 SHA。Tripod 的 `body_mass/body_inertia/geom_friction/pair_friction` 实时值作为可恢复 DR 状态单独保存，其名义模型仍须一致。当前签名面向项目使用的刚体模型，不接受 flex/plugin 模型。

**旧文件缺少物理签名、签名版本/字段不匹配或物理值改变时，在应用任何训练状态前拒绝完整恢复。** 不从旧源码或二进制哈希推断物理兼容，不自动补写旧文件身份。schema/task/架构等符合条件的旧文件仍可通过各任务 weights-only Play 使用，但不会恢复优化器、环境或随机流。这包括本轮物理签名修复之前保存的完整文件；此前 P1 的历史兼容验证不等于通过当前物理检查。

设备和依赖版本本身不门控，不等于任意设备/依赖组合均已验证。物理字段或状态布局不同仍拒绝；4050→5090完整恢复、带新签名的2048环境完整状态恢复及长期轨迹重演尚未验证。缺少签名的历史文件由当前loader明确拒绝完整恢复，不是等待大显存设备即可自动放行。

兼容性预检拒绝时不修改训练状态；应用阶段发生故障才冻结 runner 为 faulted，不报告成功。签名和兼容预检通过不等于所有历史状态都已验收。

Play是权重只读推理：任务、架构和sampling仍需匹配，有限扫描override不等于完整恢复。恢复边界或同一rollout更新的对照结果不能推导出未来物理轨迹逐位重演。

## 输出与指标

Flat v2、Terrain和Tripod使用官方 `rsl_rl.utils.logger.Logger` 的writer、`process_env_step`、`log` 和默认终端排版；`common/training_logger.py` 只做项目指标与状态的适配，不复制官方输出体。TensorBoard写入官方 `Train/mean_reward` 和 `Train/mean_episode_length`，按最近最多100个完成episode滚动平均；已有项目 `Episode/mean_return` 和 `Episode/mean_length_steps` 仍按每轮刚完成的episode计算，没有新完成episode时省略。其它项目诊断指标继续由 `learning_metrics` 产生，Terrain保留高度MSE（m²）和加权损失。

官方日志迭代索引从0开始，因此累计完成第N轮写入索引N−1；JSONL和checkpoint仍使用累计完成轮数N。续训时Runner恢复累计环境转移数，并将它作为Logger的起始统计值。官方 `totaltime` 与 ETA 只覆盖本次 `learn` 调用中的采集和更新，不含初始化、保存与日志时间；官方step统计会读取CPU/GPU数据。

每个run保存 `run_recipe.json`、`learning_metrics.jsonl`、`iteration_records.jsonl`、`tensorboard/`及checkpoint。`run_recipe.json`的`logging`字段记录Logger实现、TensorBoard索引和episode均值口径。官方TensorBoard迭代横轴从0起，项目指标的`Progress/completed_iterations`和JSONL/checkpoint仍记录累计完成轮次；`Progress/environment_transitions`为累计环境转移数，每轮新增24×环境数。官方源码diff写入 `tensorboard/git/`，Recipe与完整Checkpoint原有的 `code_provenance` 保持不变。

v1/v2/Tripod 的 Recipe 与完整 Checkpoint 均持久化启动时的 `code_provenance`：Git commit、dirty、变更路径与 staged blob / 工作树内容 SHA-256，以及汇总 `content_sha256`。忽略的日志不参与摘要；该字段不包含 diff 正文，不改 Git index。无 Git、非 Git 安装、无提交或读取不完整分别标记，不冒充 clean，也不阻止训练。摘要用于辨认实现，不能替代保存未提交源码；正式实验宜使用已提交的干净版本，运行中不要修改代码。恢复不覆盖本次启动来源，也不将它作为兼容门。

| 指标组 | 含义 |
|---|---|
| `Proprio/` | 速度跟踪均值、RMSE/MAE；速度m/s、角速度rad/s；root高度及误差m、倾角deg |
| `RewardRaw/`、`RewardContribution/` | 原始奖励及 `raw × weight × 0.02 s` 的实际贡献；可与总奖励重构核对 |
| `Episode/` | 真终止、超时、各终止原因；完成episode的回报、步数及秒数 |
| `Feet/` | 支撑脚数、足端link原点离地高度m、滑速m/s、落地事件及腾空时间s |
| `Envelope/` | 有效监督数、六维预测/目标/MAE，单位m |
| `Height/` | 仅Terrain：原始/镜像高度MSE（m²）、加权损失、有效样本和有效格比例 |
| `Scan/`、`Action/` | 近远端有效点数、动作幅度及裁剪比例 |
| `Loss/`、`Optimizer/` | PPO各项、熵、镜像/辅助损失、KL、学习率、策略标准差、裁剪比例及编码器梯度 |
| `Performance/`、`Memory/` | 采集/更新/周期保存耗时、环境步吞吐、Torch allocated/reserved/峰值MiB |

终止原因可能同时成立，计数不能直接相加解释。尚无episode结束时不伪造完整episode均值；无有效监督时省略相应均值，价值目标无方差时省略解释方差并标记无效。

足端高度使用奖励相同的link原点，不代表足底净空；平地读取平面，Terrain读取实际地形。固定六维参考下包络误差较小不等于已经学会地形记忆或行走，需结合速度、存活、奖励、动作及策略回放判断。

## Terrain 场地边界

Terrain 的有限 Heightfield 上，Root 或任一足端 link 原点查不到地面时，以 `terrain_boundary` 人工截断当前环境的 episode，再单独重置该环境；真正跌倒优先按终止处理。场地截断保留重置前观测供 Critic bootstrap，GRU 历史在新 episode 清零，不增加出界奖励或惩罚。Play 遇到边界则暂停，显式重置后继续。

出界当步，只有缺少真实地面的 Root/足端离地高度项不参与计算；其他奖励和有真值的高度项照常计算，高度统计也排除无真值点。`Episode/truncation_reason_terrain_boundary_count` 与20秒超时分别统计。11×17辅助标签仍独立使用当前 Root/Yaw 和 `terrain_world_z - root_world_z`，边缘无真值格点仍由原几何 Mask 排除，监督范围不变。

Torch显存不包含全部Warp和驱动分配，不能代替整卡显存；容量测量同时记录设备占用。指标读取和检查合批不改变奖励或更新规则。性能及历史检查结论统一见[实验记录](../../../../scripts/experiments/confined_locomotion_2/records/20261026_terrain_memory_and_performance.md)。
