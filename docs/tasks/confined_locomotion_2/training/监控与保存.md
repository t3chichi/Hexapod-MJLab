# 基础平地训练：监控、保存与启动条件

更新：2026-10-23。本页是 `_2` 训练监控和周期保存的当前说明；命令统一见[快速开始](../../../../src/hexapod_mjlab/tasks/confined_locomotion_2/快速开始.md)。奖励数值、网络和扫描设计继续由[任务入口](../README.md)引用的配置文档负责。

## 周期保存

默认 `save_interval=50`，在累计完成第50、100、150……轮 PPO 更新后的稳定边界保存 `checkpoint_full_000050.pt` 等完整状态。每轮仍为24步采集、5 epochs × 4 minibatches，不是50个控制步保存一次。续训沿用累计轮次，例如从75轮恢复，下次在100轮保存。

正常结束始终生成 `final_checkpoint_full_XXXXXX.pt`。如果结束轮次恰逢周期保存，两文件使用同一文件系统中的硬链接复用内容。文件不覆盖、不自动轮转删除；需要自行安排日志盘空间。中断或故障不会强行保存不完整的更新，可以从此前成功写入的完整文件恢复。

完整文件包含网络、Adam、两个GRU历史、环境/扫描/命令/扰动/随机流及尚未结束episode的回报和长度。`--save-interval` 可显式修改正整数间隔；它进入配方身份，严格续训需保持原间隔。`--iterations` 仍表示本次新增轮次。

本次新增指标与保存逻辑改变源码身份。20261023的旧far-hit配对短训checkpoint仍可在匹配sampling身份下用于Play，但不能在当前源码严格续训；不得重写旧身份使其通过。

## 学习指标

每轮写入 `learning_metrics.jsonl` 和 `tensorboard/`；原逐minibatch的 `iteration_records.jsonl` 保留。TensorBoard横轴为累计PPO轮次，`Progress/environment_transitions` 为累计环境转移数（每轮24×环境数）。

| 指标组 | 内容及解释 |
|---|---|
| `Proprio/` | vx/vy/wz实际值与指令均值、RMSE/MAE；速度m/s、角速度rad/s；根高度和绝对高度误差m、倾角deg |
| `RewardRaw/`、`RewardContribution/` | 原始奖励项与实际 `raw × weight × 0.02 s` 的贡献；`Reward/actual` 与重构总和可核对 |
| `Episode/` | 当轮真终止、超时及各实际终止原因计数；完成episode的平均回报、步数和秒数；未结束时不伪造完整episode均值 |
| `Feet/` | 平均支撑脚数、摆动脚link原点离平面高度m、支撑脚link原点切向滑速m/s、实际落地事件与对应腾空时间s |
| `Envelope/` | 有效监督数、六维预测/目标/MAE，均为米；无有效监督时省略均值 |
| `Scan/`、`Action/` | 实际控制输入中近远端平均有效点数、动作绝对值及裁剪比例 |
| `Loss/`、`Optimizer/` | 总/策略/价值/包络损失、熵、镜像/辅助损失、KL、学习率、策略标准差、PPO裁剪比例、裁剪前梯度范数、帧/时间编码器梯度、价值解释方差 |
| `Performance/`、`Memory/` | 采集/更新/周期保存耗时、环境转移吞吐、PyTorch allocated/reserved/峰值MiB |

终止原因可同时成立，其计数不保证相加等于终止总数。足端高度与滑速使用奖励所用link原点，不代表足底表面净空；原始腾空奖励是事件分数，不能当成实际腾空时长。价值目标无方差时省略解释方差数值，并输出有效性标记。

指标从detach后的真实transition和更新结果汇总，不修改奖励权重、PPO目标或网络结构。GPU逐步累加、每轮批量转CPU，未保存额外轨迹或计算图。PyTorch显存指标不包含所有Warp/驱动分配，不能作为整卡占用或5090容量估计；目标机容量测试还需记录整进程/整卡显存。

平地六维标签固定，且包络头有相应初始化。仅凭包络误差很小，无法证明雷达特征、时间记忆或复杂地形泛化已学会；基础训练需联合看速度跟踪、存活、奖励贡献、动作和足端行为，并回放策略。

## 5090首训前的剩余工作

用户目标为RTX5090，目标机尚未克隆仓库或安装环境；当前没有目标机容量测量。

1. **获取完整源码版本。** 基线已将 `_2`、原任务/RL依赖、机器人资产、固定通道和检查纳入明确版本；按[部署与基线](部署与基线.md)检出tag，避免误用远端旧分支。T1运行使用源码内冻结常量，不要求复制全部历史logs。目标机优先保持仓库布局并以editable方式安装。
2. **安装与真实GPU预检。** 以仓库 `environment.yml`、`pyproject.toml` 为依赖起点，核对目标机系统、驱动和实际安装版本；通过CPU检查及当前hit10的2环境1轮GPU回归，验证PyTorch、Warp、MuJoCo Warp和MJLab路径。开发机锁定组合尚未在目标5090验收，不直接宣称兼容。
3. **分级测容量与吞吐。** 固定near×6/far×10、24步、镜像和扰动，逐级增加环境数；同时测采集、20次更新、完整保存、显存峰值与持续占用。当前PPO按24步完整重放，不能直接套用legged gym的并行环境数。保留显存余量，而非选择刚好不OOM的最大值。
4. **确定有限学习预算。** 根据目标机结果选环境数与首轮预算，再做固定种子的平地学习、周期checkpoint回放和指标评估。500轮可作为首个观察段讨论，之后根据曲线决定继续、调奖励或排查网络；尚未授权启动这一训练。

现阶段无须继续改网络或预先重调奖励。首轮环境数、种子及时间预算待目标机预检和容量测量后确定。
