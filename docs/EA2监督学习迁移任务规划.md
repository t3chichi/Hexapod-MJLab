### 3.1 执行时序必须显式对齐

原执行顺序为动作映射、控制步计数、速度重采样、脚本运动、按时钟更新雷达、奖励及 oracle 更新、终止/复位、观测装配、上一动作记录。

mjlab 原生顺序与之不同。为避免“重构后能运行但语义改变”，规划如下：

- 控制步固定 `0.02 s`，`decimation=1`；动作 term 驱动一次脚本状态更新与雷达时钟，不能把运动放在奖励之后执行的 command 或 step event 中。
- 在独立的逐帧状态缓存中生成几何检查和 oracle；标签平滑每控制步更新一次。观测、奖励、可视化的重复读取不得重复推进状态。
- 计时与速度重采样采用明确的逻辑控制步号，解决 ActionTerm 执行时 mjlab 公共计数尚未递增的问题。
- 关闭 mjlab 默认奖励乘 `dt`，保持原奖励量级；原零权重项继续保留遥测能力。
- 保留原全局雷达时钟、reset stale 标记和刷新规则；不能自行改成每次 reset 强制全场刷新。
- 显式区分动作执行帧、奖励/目标帧、terminal 帧和 post-reset 观测；采集存储的观测与监督标签必须描述同一帧。
- 对整批 reset、部分 reset、路径重规划失败、超时和首次观测建立对齐检查。已核对原 BaseTask：显式 `reset()` 在复位后执行一次零动作 step。由 SL 适配器保留采集/评估入口行为，不修改 mjlab 公开 reset 语义；play 使用同一 SL 适配层，避免重复推进。
- 仅在需要保持上述旧语义处增加小范围生命周期适配，避免复制整个 mjlab 环境实现或修改安装包。

T1 的最小 GPU 验证必须先证明无关节载体、ActionTerm、管理器生命周期和真实 `Simulation` 可运行；若这一架构不能满足旧语义，暂停相关实施，报告替代设计并等待确认。

### 3.2 共享依赖如何迁移

原目录之外必需的包络范围、参数顺序、`EnvelopeConditionSpec` 及先验函数要建立来源清单并抽取必要部分。不得让新包在运行时读取旧仓库路径或依赖完整 `spider_envelop`、HAA 网络、Isaac Gym、gymtorch 或旧 rsl_rl。

保留选定通道表与姿态回放数据，作为包内资产随安装分发。通道索引、四元数约定、方向/位姿、raycast mesh 权威几何和噪声规则均需对齐。可以调用当前项目的 Warp 传感器组件，但先验证其行为；共享实现如有差异，优先做 EA2 专用适配，不顺手改变现有任务。

两种原传感器路径都保留：精简模式只投射选定187通道；完整模式投射 Airy 900×96 射线，再提取同一187通道。固定无噪声地图/位姿下比较选定通道命中与测距，证明精简模式没有改变观测含义。完整模式的其他有效点继续供红绿点云调试使用；默认训练仍采用原精简模式。

### 3.3 可视化复用边界

抽取通用绘制是可行的：mjlab 已有跨 viewer 的 `DebugVisualizer` 接口，可用于点球、圆柱线段、箭头等。因此 `utils/visualization` 只接收世界坐标点、线段或多边形及绘制样式，不读取 EA2 环境、五维参数或模型。

EA2 自己负责选择可视环境、预测/参考形态转换、雷达红绿分类和颜色规则。第一版以 native viewer 为交互验收对象；公共函数使用现有抽象，避免绑定某个任务或直接操作私有 `mjvScene`。

视觉层需要显示地图、传感器点、预测/参考包络、运动方向，并支持运行/暂停、复位和查看选定环境。训练无窗口路径不创建 viewer。公共绘制函数由第二份独立示例数据验证复用，不为此改造 `el_4090_lidar`。

## 5. 已选小规模验收配方的具体化

以下具体值作为本规划的一部分等待整体确认；保持原源码配置默认，不通过修改默认值实现小规模运行。

- 地图 seed 为 `1,7`，每图8环境，800控制步，每控制步采集；原默认障碍配置，不增加密度。
- 两张地图只采集一次，冻结文件哈希。两套配方共用这些数据和相同train/val split，不分别重采集，不额外扩大数据预算。
- 训练窗口400步、stride15、warmup30步、按原规则以环境划分验证集，split seed=1。
- 默认模型 `GRU(190→187)` + `MLP(256,128→5)`，沿用原 batch size64、lr=1e-3、梯度裁剪1.0、5轮训练，训练随机 seed=1。
- 默认配方：回忆头关闭、安全损失系数0；额外配方：`aux_ks=[25,50,100,200,300]`、`aux_mode=recall`、总权重0.5、安全损失系数1.0，其他规模相同。两套模型从各自可复现初始化训练并分开保存。
- 每套模型重载后在两个地图上各8环境、700步评估，覆盖 stateful/window 及 zero-action/常量基线，保留原指标和配置来源。
- 姿态回放能力保留，另做短时开启 smoke，核对 pitch/roll/height 与通道读数有限；不额外增加大规模姿态语料训练。
- play 用1个环境、已保存模型；完成交互与绘制验收，不为了可视化重跑训练。
- 每个 pipeline 阶段明确参数和产物目录；发现原入口默认值不一致时，不自行统一它们，而以已确认显式验收命令消除歧义。

小规模预算证明流程和学习机制，而不是重现 README 的历史 R²/碰撞率门槛。“与原效果对齐”的证据分为：固定输入/权重的数值对齐，以及相同小规模真实数据上的训练与评估；历史训练效果在缺少模型/数据且预算不同的情况下不可宣称已复现。

若5轮未显示有效学习，报告数据变化量、train/val损失、常量基线与失败原因，由用户决定是否追加预算；不能自行扩到50轮。数据缺少收缩事件或 target 方差过低时，验收不能仅以文件成功产出判通过。

拟定可判定的最低验收门槛，随总规划一并确认：

- 去除warmup后，至少一维归一化目标的标准差 `≥1e-3`，且任一维归一化extent `≤0.8` 的有效帧占比 `≥1%`，用于排除全程近常量或没有收缩事件的数据。
- 两配方的主训练MSE均有限，最后一轮相对首轮下降至少 `5%`；验证指标完整、有限，最佳checkpoint在独立重载后输出最大差异 `≤1e-6`。不要求小预算达到历史R²门槛。
- 每档回忆头在有效时间对上存在有限非零梯度；固定几何违规但非floor-pinned样本的安全损失及参数梯度非零，安全/floor-pinned样本遵循原掩码规则。真实训练中的触发率另行记录，不强行要求每个batch都有碰撞。
- 任一门未满足都保留失败结果，分析后询问；不得为了通过而暗改seed、标签、门槛或训练轮数。

## 6. 验收与审查规则

### 6.1 数值对齐

- 整数内容（通道索引、占据栅格、采样索引）要求相同；浮点几何、映射、纯网络以最大误差 `1e-6` 为拟定门槛。
- GPU射线、姿态与复合几何按相同固定地图/位姿/方向逐项比对；噪声关闭的固定非擦边用例要求命中标记一致，命中测距 `atol=1e-4 m、rtol=1e-5`，未命中sentinel一致；完整与精简模式选定187通道采用同一判据。擦边用例另外记录数值和几何位置，不将其混入稳定用例掩盖错误。噪声开启时检查公式、范围、调用次数和随机化分布，不要求不同后端的随机值逐位相同。
- 如果存在必须采用不同容差的引擎差异，记录数值与原因，先确认再调整门槛。
- 使用只读隔离加载原纯模块或预先冻结的源fixture作为参考；不能用新实现生成自己的“golden”。不启动旧Isaac训练或改变旧团队仓库。
- 序列/逐帧 GRU、checkpoint 重载、归一化↔物理值、后缘反向符号和辅助损失梯度必须检查。

### 6.2 时序与数据

传感器更新、脚本运动、oracle和平滑更新、reset stale、terminal/post-reset、观测标签配对、训练窗口done隔离分别设置检查。小规模800步不覆盖45s超时，因此超时和部分reset须以专门短回合配置验证，不改变验收训练配置。

观测范围、训练/验证分离、数据版本和源地图必须记录。不同地图的安全loss只查询各自距离场；不可行最小包络掩码与原规则一致。

### 6.3 流程与现有任务回归

完整pipeline必须在新进程独立重载模型后执行真实mjlab环境评估。故意不向运行提供旧仓库路径，核查安装包中的通道和姿态资产；工作目录变化不能导致找不到资源。

现有任务的注册、配置、动作/观测维度及共享传感器不变。重跑既有CPU核心检查，并在GPU上做小环境数的 Gate A/B；不为回归追加旧任务长时训练。

训练、GPU和GUI依赖使用现有 `hp_mjlab`。若缺少额外依赖，列明用途与是否必要，在安装前确认。不会升级torch、mjlab等已验证依赖组合或修改安装包。

### 6.4 审查职责

主代理实施与汇总；独立子代理只读检查规划/代码/验证证据。每阶段审查记录具体文件、问题、修正和复检结果；关键问题未解决不进入依赖阶段。既有“对齐旧实现”不能代替检查旧缺陷，旧缺陷的处理遵循第7节用户决定。
