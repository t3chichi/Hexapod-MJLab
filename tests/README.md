# tests/ — verification gate map

One-shot verification gates for the `Lidar_legged_gym → Hexapod-MJLab` migration
(background: [MIGRATION.md](../MIGRATION.md)). Reusable tools, generators and
benchmarks live in [`scripts/`](../scripts/) instead — `scripts/tools/`
(`urdf_to_mjcf.py`, `golden_terrain_gen.py`, `baseline_compare.py`),
`scripts/bench/` (throughput / friction benchmarks + baseline launchers) and
`scripts/spike/` (`lidar_warp_spike.py`).

All commands run in the conda env `hp_mjlab` unless noted otherwise.

## Conventions

- Script-style tests: each prints a JSON verdict (or per-check `ok:`/`FAIL:`
  lines) and exits 0/1 — run them directly with `python`, no pytest runner
  involved.
- Logs and artifacts (JSON results, PNGs, generated MJCF/.bin) land under each
  group's own `logs/` dir (e.g. `tests/lidar_sensor/logs/acceptance/`,
  `tests/terrain/logs/`), which is gitignored via the `logs/` pattern.
  This is the **test-local** logs rule: small acceptance artifacts stay next
  to the test that produced them. Training runs live elsewhere — mjlab
  training output goes to the top-level `logs/rsl_rl/{experiment}/{ts}/`
  (mjlab's official default, see its `scripts/train.py` +
  `docs/source/training/rsl_rl.rst`) and the m5 baseline harness writes its
  metadata to `logs/m5/` (see `scripts/bench/m5_run_baseline_*.sh`); the retired
  `runs/` root no longer exists.
- GPU tests are short (seconds); the heavyweight benchmarks/baselines
  (`scripts/bench/run_baseline_*.sh`) are intentionally excluded from this directory.

## Known flakiness

- `terrain/hfield_check.py`: mujoco-warp's HFIELD-BOX contact (≤1 contact
  point under MULTICCD, see MIGRATION.md M2 decision 6) is not run-to-run
  deterministic; occasionally a world's box jitters or wanders at step 300 and
  `at_rest_speed`/`at_rest_drift` (or `resting_on_pillar`) fail despite the
  CPU reference resting cleanly. Observed ~1 failing run in 3 at HEAD
  `79dd370`, identically before/after the 2026-09-29 reorg (the move is not a
  factor — deterministic outputs are bit-identical). Re-run on failure before
  investigating.

## EA2 supervised-learning migration

`tests/ea2/` contains the approved staged gates. Run from the repository root
with `PYTHONPATH=src` in `hp_mjlab`; logs are in `logs/ea2/acceptance/` so they
can be kept together with the frozen-data pipeline evidence.

| Script | Verification | Device |
|---|---|---|
| `platform_gate.py` | Actual manager environment, action/observation contract and clock/reset | GPU |
| `numerical_gate.py` | Frozen-source geometry, oracle, smoothing, maps, paths and noise formula | CPU |
| `environment_gate.py` | Motion, reduced/full raycasts, timing, terminal/reset and attitude replay | GPU |
| `supervision_gate.py` | Old weights/windows, recurrence reset, areas, auxiliary gradients, map IDs and target timing | CPU |
| `collection_gate.py` | Real short collection, save/load and rollout | GPU |
| `visualization_gate.py [--full-lidar]` | Native viewer controls, bounded render and independent drawing example | GPU + display |
| `packaging_gate.py /path/to/package.whl` | Wheel assets and isolated imports without old runtime modules | CPU |

The source-comparison gates read the original repository at
`~/el4090_legged_gym` and verify its manifest first. EA2 runtime modules and
wheel imports do not depend on that repository. The five-epoch learning gate
is the separate `sl.scripts.pipeline --small --play` command documented in
the root README; it must not silently enlarge its data or epoch budget.

## EA2 static oracle experiment

The approved offline experiment reads the frozen small migration corpus; it
does not replace the production oracle or train a network. Run from the root
with `PYTHONPATH=src OMP_NUM_THREADS=1` in `hp_mjlab`, in this order:

| Script | Verification/output |
|---|---|
| `ea2/static_oracle_gate.py` | Six synthetic classes, 16 analytic pose/margin cases and independent geometry probes |
| `ea2/static_oracle_compare.py` | Every one of the frozen 12,320 valid poses; original and matching-margin baselines; exact whole-polygon validation |
| `ea2/static_oracle_diagnostics.py` | Saved-result denominator clarification, fixed batch/source and dense-boundary audits; no new full candidate run |
| `ea2/static_oracle_report.py` | All-pose coverage, common-safe shape/adjacent-change metrics and PNGs; synthetic baseline illustration |

CPU only; existing SciPy, no new dependencies. Evidence goes to
`logs/ea2/oracle_static/20261003/`. Correctness PASS is separate from efficacy;
see [the experiment record](../docs/tasks/envelope_adaptive_2/oracle/实验记录.md) for results and limits.

The default EA2 teacher is now the whole-polygon causal provider. Historical
source gates explicitly retain `oracle_kind="legacy"` where they inspect the
old smoother. New release gates are `teacher_supervision_gate.py` (masks,
NaN/gradient isolation, public API provenance, paired areas),
`teacher_environment_gate.py` (real cached reads/partial reset/online parity),
`teacher_frozen_parity.py --tag <new-tag>` (all selected frozen frames), and
`teacher_release_pipeline.py` (frozen release corpus, two SL recipes, rollout,
export and play). The release harness preserves existing evidence and assumes
its named data has already been collected. New outputs must use a new run name.
